# Skill: stage-pitch

When the user asks for a **pitch / elevator pitch / stage pitch** of this project:

1. Speak as if on stage to a Meetup audience — short, spoken cadence, no essay.
2. Use exactly **three beats** (≤12 lines total):
   - **Hook** — one sentence: what problem this solves (agents with skills + memory,
     built 100% on Cursor CLI).
   - **Proof** — three concrete pieces the audience can see live: a skill trigger,
     lazy `MEMORY.md` load, and either cron finding or worker dispatch.
   - **Close** — one sentence inviting them to try the repo / fork the pattern.
3. Prefer bullets over paragraphs. No absolute home paths, no private tool names,
   no personal names — keep it generic and reusable.
4. If they ask in Spanish, answer in Spanish; otherwise English.
5. Do not invent features that are not in this repo. If unsure, peek at
   `README.md` / `ARCHITECTURE.md` first.
