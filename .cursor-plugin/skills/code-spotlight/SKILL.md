# Skill: code-spotlight

When the user wants to **spotlight / highlight / show on stage** a file or symbol:

1. Read the named path (or the symbol they point at) before answering — never invent.
2. Reply with a stage-ready card (≤5 bullets, ≤10 lines total):
   - **What** — one sentence (file purpose).
   - **Where** — `path/to/file.ts` and the key export/function name.
   - **Why it matters** — one sentence for the Meetup story (skills, memory, cron,
     or worker dispatch).
   - **Watch for** — one concrete line/behavior to glance at during the talk
     (cite with a start:end:filepath fence if pointing at a specific block).
   - **Skip** — one thing the audience can ignore so they stay focused.
3. No wall of code. Max one short citation fence.
4. If the path is missing or ambiguous, ask which file — do not guess.
